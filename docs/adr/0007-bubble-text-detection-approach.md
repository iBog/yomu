# Yomu keeps the incumbent YOLO26n bubble/text detector

> **Revised in part by [ADR-0020](0020-selectable-text-detector.md).** YOLO26n stays the default, and the detection slot also offers ogkalu's RT-DETR text detector as Experimental, because YOLO26n misses text in rectangular captions.

> **AGPL clearance resolved by [ADR-0019](0019-yomu-is-agpl-open-source.md).** Yomu is published under AGPL-3.0, which meets the YOLO26 base's terms. The "Per ADR-0001, Yomu ships closed-source" premise below no longer holds, and neither the Enterprise licence nor a retrained detector is needed for licensing.

Yomu detects bubble and in-panel text with the `Kiuyha/Manga-Bubble-YOLO` **yolo26n** ONNX model already in production — a single-class `Text` detector, run at confidence 0.25 through the existing `nonMaxSuppressDetections` (NMS IoU 0.80). No model is swapped in, no threshold moves, no post-processing is removed. The candidate that could have replaced it — the `small` variant from the same repo — was measured against it on the ADR-0003 containment criterion and lost.

This is a hold decision, not a default. The candidate set that survived #27's survey collapsed to exactly one deployable alternative, and a paired on-device run (#57) settled it on the eval's real gate rather than on vendor headline numbers.

## Considered Options

- **Keep the incumbent yolo26n.** Chosen. Story containment **0.724** (105/145 boxes), localisation 0.876, 19 merging, 26 false positives, ~482 ms/page (SM-S911B, #57). Single class, ONNX, already loaded by `OnnxRuntime` and wired into `BubbleDetector` → `OverlayService`. Zero integration cost.
- **Swap to yolo26s (`onnx/yolo26s.onnx`, same repo).** Rejected on measurement. 20.3 MB vs 6.1 MB, 9.5 M params vs 2.4 M, same single class and output shape — a URL swap, no second runtime. Vendor card reads better (P 0.937 / R 0.893 / mAP@50 0.961 vs 0.929 / 0.863 / 0.947), but the vendor recall gap did not survive the containment criterion: paired, **0.717 vs 0.745 own-best-pad (−2.8 pp — worse)**, identical 19 merging, and **2.3× slower** (1101 ms vs 482 ms). Under the pre-registered swap rule below, the incumbent holds outright.
- **comic-text-detector** (manga-image-translator). Rejected before scoring: GPL-3.0 and no documented ONNX/TFLite/NCNN export — the highest integration cost in #27's survey.
- **kitsumed-seg fine-tune.** Rejected: GPL-3.0.
- **ogkalu YOLOv8m fine-tune.** Rejected: 25.9 M params (10× the incumbent), `.pt` only (hand export needed), and the same Ultralytics-AGPL base question — a much larger model to score, with no published accuracy, for no expected win.
- **Magi ("Manga Whisperer").** Rejected: academic-licence-only, GPU-oriented, no mobile path. An accuracy ceiling, not a candidate.

## Consequences

**The swap rule was pre-registered before #57's numbers existed.** #44 established that a sub-8pp containment gap is unresolvable on this corpus at any achievable size, so a small bump could not justify a larger model. The rule, written into #57 before the run: **≥8 pp containment separation → swap; below that → the challenger wins only by strictly reducing merges; otherwise the incumbent holds** on size and integration (incumbent-wins-ties, the precedent ADR-0005 set for OCR). Wall-clock is a veto on the winner, never a ranking input. yolo26s came in at −2.8 pp with equal merges — it fails every branch.

**Confidence stays at 0.25.** #57 swept 0.25 / 0.35 / 0.45 / 0.55 on the incumbent: containment falls 0.745 → 0.676 while false positives barely move (23 → 19). Raising the threshold trades away the gate to shave a handful of false positives the eval does not gate on. 0.25 is kept.

**NMS is kept — it fires.** YOLO26's head is advertised end-to-end NMS-free, so #57 was asked whether `nonMaxSuppressDetections` ever removes a box; if it never fired, this ADR would delete it rather than leave dead post-processing. It fires: raw→kept 139→136 and 129→127 across the run (3 and 2 boxes removed). The "delete if never fires" branch is void. NMS stays at IoU 0.80.

**No per-box class label. ADR-0002's class marker is dropped.** #31 carried a requirement here: decide whether the detector exposes speech / narration / sfx. No candidate does — the model card publishes exactly one class, `Text`; `parseYoloDetections` (`ml/src/main/java/com/yomu/ml/OnnxRuntime.kt:290`) keeps only `classId == 0` and hardcodes `label = "bubble"`; and #44 deleted the eval's per-class rows as fabricated by substring heuristic, so no ground truth exists to score a class against. Deriving the class heuristically at runtime from box geometry was rejected outright: it manufactures a field flowing into the translation prompt, and this map has already found four fields that looked wired and were not (`sessionContext` twice, `Bubble.textRegion`, the eval class labels). A fifth, invented on purpose, is not a trade worth making. ADR-0002 receives an **amendment** pointing here, not a silent edit — an ADR is a decision log, and erasing the class field would erase why it died. Revisit only if a multi-class manga detector with published weights appears.

**Yomu translates balloon and in-panel text; title, credit, and cover text are out of scope.** ADR-0003 left this product call here. Two of the three genuinely-unfound story boxes on the original eight pages were unenclosed horizontal title/credit text, and cover pages score 0/3 containment. Taking them in scope would mean swapping a balloon detector for a general text detector and re-opening the entire candidate set, to serve a page the reader looks at once. Those boxes **stay in the reported denominator** per ADR-0003 (excluding them would make the same decision by omission) but are never gated.

**No absolute pass bar.** A consequence of the scope call: with unenclosed text unreachable by any balloon detector, a bar near 1.0 would be unmeetable and would silently re-decide the scope question. Candidates are gated **relative to the measured incumbent** (story containment 0.724), never against an absolute floor.

**Merging is a tie-breaker with teeth, not a gate.** The incumbent's 19 merging detections cost ~22 boxes under ADR-0003's one-to-one rule, and NMS cannot fix any of them — a merge is one detection covering two bubbles, not two overlapping detections — so under ADR-0002's id addressing each merge fuses two speakers into one id while another id never appears. A challenger tying on containment and merging strictly less would win outright. None does; there is no absolute merge bar and no evidence any detector of this class does better.

**AGPL clearance is a named, unresolved shipping precondition — it does not gate this decision.** `Kiuyha/Manga-Bubble-YOLO` declares `apache-2.0` on its card but is a fine-tune of Ultralytics YOLO26, which is **AGPL-3.0**; an uploader relabelling a derivative does not override the base project's terms. Per ADR-0001, Yomu ships closed-source, so this is exposure on **what is already in production**, not a hypothetical about a future pick. Both variants share the same base, fine-tuner, and card, so the licence question does not separate them and cannot break the technical tie. This ADR decides on technical merit and records AGPL clearance as a precondition the build effort must clear before shipping — legal input, not a map ticket; stalling the route on counsel's calendar buys nothing. The one clean technical exit, named here so it is not re-derived later: **train Yomu's own detector on Manga109-s** (whose licence permits commercial use of *results*) with an Apache-2.0 architecture — a training project and a separate effort, not a model pick. Buying an Ultralytics Enterprise licence is also a real answer, but it is a purchase decision that does not change which model runs.

**Nothing is built by this decision.** *(The detection criterion is superseded by [ADR-0015](0015-quality-belongs-to-the-model.md), and the instrumentation below is removed with the eval code; a future challenger is chosen per that ADR, not by one run.)* The incumbent holds, so there is no detector-swap work. The instrumentation #57 added — second-detector staging from test-APK assets, `conf` / wall-clock / NMS emission, `score-detector-comparison.py` — stays in the tree so any future challenger is a URL swap plus one run. The ADR-0003 app-side consequences (the 4% crop pad in `CropBoundsCalculator`, deleting `Bubble.textRegion`) remain owned by ADR-0003's post-map build, not by this ADR.
